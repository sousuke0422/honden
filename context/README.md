# context — 案件ごとの覚書

任（task）に `project:` が書いてあれば、足軽はここの `<project>.md` を読む。
無ければ読むものは無い。それで正常である。

## 何のための物か

**新しく入った足軽への引き継ぎ**である。
その案件で働くのに要る最小の知識——場所、決めたこと、踏んではならぬ罠——を
一枚に置く。session を跨いで残り、/clear の後も任の YAML と併せて立て直せる。

## 何のための物では**ない**か

設計書の置き場ではない。
旧環境の `context/` は同じ意図で始まり、**一つの案件の書が 80KB・1,214 行の
設計書に育った**（investment-support・2026-06）。読むだけで足軽の文脈が尽きる。
当時の雛形は「シンプルに保つ」と定めていたが、定めだけでは止まらなかった。

- 設計と裁定の記録 → その案件の repo の docs へ
- honden 自身の裁定 → `docs/decisions.md`
- 殿の好みや教訓 → memory

`honden projects` は覚書の大きさを見せ、育ちすぎていれば警める。

## 雛形

```markdown
# <project>
最終更新: YYYY-MM-DD

## 何か
一、二文。

## 場所
- path: …（work_location: coder なら「WSL は参照専用・push 403」も書く）

## 決めたこと
- …（理由を一行添える）

## 罠
- …（実際に踏んだ物だけ。想像の罠は書かない）
```

## 作法

- 決めたことが増えたら**その場で**書き足し、日付を上げる
- 要らなくなった行は消す。**足すより消す方が価値がある**
- この dir は README 以外 git に載らない（案件の中身は私事でありうる）
